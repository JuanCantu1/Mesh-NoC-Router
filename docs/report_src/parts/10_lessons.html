Lessons, corrections and what went wrong

A project record that lists only successes is not trustworthy. This chapter collects the defects, wrong turns and corrections found along the way, how each was found, and what it changed. Several of them are the reason a later check exists.

Tooling lessons

  • Windows line endings. Python wrote carriage returns in text mode, which blinded shell substitutions in the mutation script. Source files were normalized, and Python now writes with explicit newline control.
  • Paths with spaces. SymbiYosys cannot take spaces in file lists, so the proof scripts use relative paths from each proof's directory. It also exits non-zero on an expected FAIL, which broke scripts running with pipefail; the verdict is now read from the last "DONE" line.
  • Parallel synthesis. Running eight Yosys jobs at once crashed from memory pressure. The script uses three or four in parallel with a retry.
  • Result parsing. A flop-count parser missed numbers in scientific notation until it was fixed.
  • Bash heredocs and embedded Python. Escaping broke inline scripts repeatedly; analysis code lives in files.

Cross-cutting lessons

  1. Verify the thing that decides the answer. Timing from one router, throughput from light-load tests, security from a defense never shown to fail: each looked fine and each was wrong or empty.
  2. Make every refactor prove it changed nothing. Equivalence against the previous milestone turned "I think it's the same" into 288 matching runs, and made later timing changes safe.
  3. Check the checkers. Mutation testing found a redundant mutant, a false-positive hazard and invisible-to-stimulus bugs. Negative controls did the same for the proofs.
  4. Predict, then measure. A model that says where each pattern must saturate turned one surprising result (uniform traffic) into a finding with a cause. Without the model it would have read as "about 75%".
  5. A testbench is a design. It needs the same care about timing and races as the RTL. The two worst debugging episodes were testbench bugs.
  6. Correct the record where the claim lives. M7's original document now opens with its correction.

What would be done differently

  • Synthesize the whole mesh from the first synthesis milestone, and compare with the single-router number as a cross-check.
  • Put the log-gating wrapper in every run.sh from M1, instead of adding it at the end.
  • Build the replay checker before the replay page.
  • Keep one shared testbench library for the credit-tracking and scoreboard code, instead of carrying copies forward and fixing a race in each.
