What one router does with a flit

    
Each router has five ports: north, south, east, west, and local (its tile). Packets are single flits carrying a message class, source, destination and a 16-bit payload. Flow control is credit-based: a router sends on an output virtual channel (VC) only when it holds a credit for a free slot in the downstream buffer, so nothing is ever dropped for lack of space.

    

      

        On arrival
        
Buffer write and route

        
The flit is written into the FIFO of the VC it arrived on. Its output port is computed on the way in, X first then Y, and stored next to it as a 3-bit tag, which takes route computation off the critical path.

      

      

        Pipeline stage 1
        
Allocate

        
Each waiting flit claims a free output VC inside its virtual network (round-robin). The switch allocator then matches inputs to outputs, separable input-first, with a second pass that fills ports the first pass left idle. The winner is muxed out of its VC into the pipeline register and spends one credit.

      

      

        Pipeline stage 2
        
Traverse

        
The flit crosses the 5×5 crossbar and the link, and lands in the next router's buffer at the next clock edge. When that buffer later pops it, a credit travels back upstream.

Hardened local port (SECURE=1)

        
    
          
  • Source stamping. The router overwrites each injected flit's source field with its own coordinates, so a tile cannot spoof another.
    • 
          
  • VN guard. A flit injected on a VC outside its class's virtual network is refused, and its credit is never returned, so a tile that cheats only starves itself.
    • 
          
  • Credit-starvation watchdog. If a tile leaves delivered flits waiting with no credit back for 256 cycles, the router quarantines it and discards traffic addressed to it.

Where this data comes from

    • 
          
  • tools/vcd2json.py samples every router port and every FIFO's contents just before each rising edge.
    • 
          
  • tools/check_replay.py rejects the data unless every link handoff lands in the right downstream VC one cycle later, every hop follows XY routing, no flit leaves its virtual network, and no FIFO exceeds its depth.
