Motivation and scope

The problem: moving messages on a chip

A modern processor is no longer one core and a memory. It is dozens of agents: cores, cache slices, memory controllers, I/O blocks and accelerators. They all need to talk to each other, and the traffic between them decides how fast the whole chip runs.

A single shared bus cannot carry that traffic. Only one agent can speak at a time, and the wires get longer and slower as agents are added. The standard answer is a network-on-chip: each agent attaches to a small router, routers connect to their neighbors, and a message hops from router to router until it arrives. The usual layout for large chips is a two-dimensional mesh, because it is regular, it maps naturally onto a floorplan, and its wires are all short.

The router is the building block, and its design decides three things about the whole network:

  • How much traffic it carries (bandwidth) and how quickly (latency).
  • Whether it works at all, because a network that can deadlock under the wrong traffic mix is broken no matter how fast it is.
  • What it costs in area and in clock frequency, since the router sits on the critical path between every pair of agents.

Why this project

The project has one technical aim and one practical one.

Technical aim. Build a real router the way a design team would, and answer four questions with evidence rather than opinion:

  1. Performance. Where does a simple router lose bandwidth, and what fixes it?
  2. Correctness. What breaks when different message types share buffers, and what prevents it?
  3. Trust. What can a single misbehaving agent do to everyone else on a shared fabric, and how is that stopped at the cheapest possible point?
  4. Implementation. What does each feature cost in silicon area and clock period, and which router should a given chip actually build?

Practical aim. Produce a complete RTL design and verification portfolio piece: a design with a specification, an architecture that evolves for stated reasons, a layered verification environment, synthesis and formal results, and honest documentation of what worked, what failed and what was corrected.

Head-of-line blockingA simple router with one queue per input wastes link bandwidth: a flit waiting for a busy output blocks everything behind it, even flits bound for idle outputs. Scope

In scope

  • A 5-port mesh router with XY routing, in SystemVerilog, for mesh sizes up to 16×16 (4-bit coordinates)
  • Credit-based flow control, virtual channels, virtual networks, a two-pass allocator, an optional second pipeline stage
  • A three-class coherence-style traffic model (request, snoop, response)
  • Defenses at the tile port against one compromised tile
  • Synthesis on sky130, formal proofs, lint, mutation testing, analytic checks
  • A replay visualizer for the final design

Out of scope, on purpose

  • Multi-flit wormhole packets (head, body, tail handling)
  • Adaptive routing, non-mesh topologies
  • Placement, routing, and sign-off timing
  • Real workload traces; only synthetic patterns
  • Rate limiting, confidentiality and side-channel defenses
  • A full coherence protocol; the protocol model only has to create the dependency chain that causes deadlock

Keeping packets to a single flit is the largest simplification. It keeps the router small enough to verify completely, and every result in this report is stated for that case. Chapter 10 describes what multi-flit packets would add.

How "done" was decided

The project follows four rules about when a milestone is finished:

  1. Its own regression passes, and the script exits with an error if any step does not print its pass line.
  2. Every claim in its write-up is backed by a command that reproduces it.
  3. If it changes an earlier design, it is configured to behave as that design and must reproduce the earlier results exactly.
  4. Any defect found in an earlier result is corrected openly, in the earlier document, not only the later one.

Rule 4 was used. M8 found that M7's timing method overstated its fixes by about a factor of two, and M7's write-up now carries a correction note at the top (Chapter 9).
